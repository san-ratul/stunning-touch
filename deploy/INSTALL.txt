================================================================
 STUNNING TOUCH — cPanel DEPLOYMENT GUIDE (no SSH, no Composer,
 no Node.js on the server)
================================================================

The deployment ZIP contains the COMPLETE application (Laravel + production
vendor/ + compiled assets) at its root, plus a temporary browser installer.
Extract it directly into your document root — exactly like the proven
MovieHub deployment.

STEPS
-----

1. CREATE THE DATABASE
   cPanel -> MySQL Databases:
   - create a database (e.g. stunning_stunningtouch)
   - create a database user
   - grant the user ALL PRIVILEGES on that database
   - note the exact database name, user and password

2. UPLOAD & EXTRACT (into the document root)
   cPanel -> File Manager:
   - upload stunningtouch-deploy.zip into public_html/
   - extract it THERE and choose "overwrite / replace all" when asked
   - result: the application files sit directly in public_html/
     (app/, vendor/, public/, index.php, .htaccess, install.php, ...)

   NOTE: if public_html already contains another site, back it up first
   or deploy to a subdomain instead.

   Cleanup of an older failed attempt: the installer detects leftover
   folders (stunningtouch-app/ from older package versions, or a nested
   public_html/public_html/) and offers to delete them for you
   ("Delete stale folders" on the requirements screen) — it runs as the
   web-server user and can usually delete files File Manager cannot.

3. RUN THE INSTALLER
   Open:  https://yourdomain.com/install.php
   (While the app is not installed, every URL automatically lands here.)

   - Paste the installation key: it ships inside the ZIP as the dotfile
     .install-key (never web-readable) and is also saved locally by the
     builder as deploy/INSTALL-KEY.local.txt.
   - System requirements are checked (PHP 8.3+, extensions, files,
     permissions).
   - Enter your domain (https://), application name, timezone, the MySQL
     details from step 1, and YOUR administrator email + password.
   - The installer validates the database connection and refuses to touch
     a non-empty database that was not created by this installer. A failed
     previous attempt (partial migration run) is reset automatically.
   - It then writes .env (fresh APP_KEY + scheduler secret, file-based
     sessions/cache for maximum shared-hosting compatibility), runs
     migrations + seeding through the Laravel framework API (no shell
     commands), creates your admin account (removing the well-known
     seeded default account), sets up public storage (symlink when
     allowed, copy otherwise), and deletes itself.
   - A permanent marker (storage/app/installed) locks the installer.

4. VERIFY THE SITE
   - https://yourdomain.com/              (homepage)
   - https://yourdomain.com/merge-pdf     (a tool page)
   - https://yourdomain.com/admin/login   (admin panel)
   - https://yourdomain.com/.env          (MUST be 403/404, never content)

5. CONFIGURE AI PROVIDERS
   Admin -> AI Provider: endpoint + API key, "Fetch Available Models",
   choose a model, Test Connection, save. Credentials are stored
   encrypted in the database — never in .env.

6. cPanel CRON JOB (scheduler)
   cPanel -> Cron Jobs -> once per minute. Use YOUR scheduler secret from
   .env (the value of SCHEDULER_SECRET):

     * * * * * /usr/bin/curl -s -m 55 "https://yourdomain.com/run-scheduler/YOUR_SCHEDULER_SECRET" > /dev/null 2>&1

   If the host provides a PHP CLI, the equivalent is:
     * * * * * cd /home/USERNAME/public_html && php artisan schedule:run >> /dev/null 2>&1

7. OPTIONAL PERFORMANCE
   If you can run PHP once (cron or cPanel Terminal):
     cd public_html && php artisan optimize

TROUBLESHOOTING
---------------
- "checkdir error: Permission denied" while extracting / cannot delete
  old folders:
  The old folders are owned by the web-server user. Open the installer
  and use its "Delete stale folders" action, or set the folder
  permissions to 755 in File Manager and delete; the host can reset
  ownership if needed. Then re-extract with overwrite.

- Database connection failed:
  Check the cPanel-prefixed DB name/user, the password, and that the
  user has ALL PRIVILEGES on the database.

- Missing PHP extension:
  cPanel -> MultiPHP Manager / Select PHP Version -> enable it.

- Storage symlink blocked:
  The installer copies media into public/storage instead. After future
  media uploads, copy storage/app/public to public/storage again — or
  ask the host to enable symlinks.

- HTTP 500 / blank page:
  Check storage/logs/laravel.log and storage/logs/installer.log. Common
  causes: PHP below 8.3, or a stale .env from an old attempt (delete
  .env and reload install.php).

- Missing styles / assets:
  public/build must exist — re-extract the ZIP with overwrite.

- Installer already disabled ("permanently disabled" page):
  storage/app/installed exists — the app is installed. Only delete that
  marker AND use a fresh empty database if you truly need to reinstall.

- Installer key missing/wrong:
  The key ships inside the ZIP as .install-key and a copy is saved
  locally as deploy/INSTALL-KEY.local.txt at build time.
